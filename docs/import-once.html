Abstract

This chapter supports researchers in importing data from various sources and file formats commonly used in public health research. Researchers re-read the import line they first ran in Coding a Plot, learn its three parts (object, function, file path), import the same data as a .csv and as an Excel file, and inspect the result with head(), names(), nrow(), and ncol(). The chapter demonstrates essential data inspection techniques including viewing data structure, examining headers, and understanding data summaries. Researchers also learn to handle missing data by recoding special values (-99, -50) as NA during import. By the end of this chapter, researchers will be equipped to import data from multiple sources and prepare it for analysis in their public health research projects.

Keywords

data import, csv, excel, SPSS, missing data

9.1 Introduction to Data Import

The first step of the data science workflow is to import your data: to bring a file from your project folder into R’s memory, as an object you can use. Public health researchers import data from many sources: survey platforms (Qualtrics, REDCap), spreadsheets (Excel, Google Sheets), other statistical software (SPSS, SAS, Stata), and R packages. In FRI Public Health, your team’s data comes from Qualtrics as an Excel file (Export Survey Data).

You have already imported data once. In Coding a Plot, the first line of code was:

insurance <- read.csv("data/insurance.csv")

You watched it run without an explanation. Now you will read it, because every import you ever write has the same three parts.

9.2 📋 The Play

9.2.1 Play 1: Read the import line

insurance <- read.csv("data/insurance.csv")
Part What it is What it does
insurance the object name you choose the labeled box that will hold the data (Coding a Plot)
<- the assignment arrow “put what is on the right into the box on the left”
read.csv( ) the function reads a .csv file (comma-separated values, a plain-text spreadsheet)
"data/insurance.csv" the function’s input: a file path in quotes the folder data inside your project, then the file name, then its extension .csv

Read it from right to left: open the file insurance.csv in the folder data, read it as a table, and call that table insurance. R looks for the data folder starting from your project folder, which is why the project matters (R Software). Nothing appears on the screen when this line runs. Look at the environment tab instead: insurance is there, with its number of rows (obs.) and columns (variables).

head() is also how you catch the two most common import problems at once: a first row that is question text instead of a person (two header rows, Export Survey Data), and a column of numbers that came in as text (the values are in quotes, or the column shows <chr> instead of <dbl>).

Try it. Run head(insurance), then change it to head(insurance, 10) and to tail(insurance). The second input to head() is the number of rows; tail() shows the last rows instead of the first.

9.2.3 Play 3: Same play, Excel file

Your team’s data is an Excel file (.xlsx), not a .csv. The import line has the same three parts. Only the function changes, because the file type changed, and that function comes from the readxl package, so library(readxl) has to run first (R Packages).

library(readxl)
insurance_xl <- read_excel("data/insurance.xlsx")
head(insurance_xl)
# A tibble: 6 × 7
    age sex      bmi children smoker region    charges
  <dbl> <chr>  <dbl>    <dbl> <chr>  <chr>       <dbl>
1    19 female  27.9        0 yes    southwest  16885.
2    18 male    33.8        1 no     southeast   1726.
3    28 male    33          3 no     southeast   4449.
4    33 male    22.7        0 no     northwest  21984.
5    32 male    28.9        0 no     northwest   3867.
6    31 female  25.7        0 no     southeast   3757.

Compare the two head() outputs. Same people, same variables, same numbers. The file type does not change the data; it only changes which function reads it. (read_excel() prints the output as a tibble, which shows the number of rows and the type of each column, such as <dbl> for numbers and <chr> for text, under the column names. That extra line is useful, not a problem.)

For your team’s data, the line looks like this (Team 1, exported on the October 9 lecture; the object is named alldata because it holds every response, and later chapters filter it down):

alldata <- read_excel("data/10.09.2026.data.team1.clean.xlsx")

An Excel file can hold several sheets. read_excel() reads the first sheet unless you say otherwise, and Excel names that sheet Sheet1 by default. Your .clean file has one sheet, and the lab file keeps its data on the first sheet, so in both cases the file name is enough. If you ever need a different sheet (the lab file also has a codebook sheet), add a second input, sheet =:

mh_codebook <- read_excel("data/ANTH306_LayConceptionsMH_SYNTHETIC.xlsx", sheet = "codebook")
ImportantRequired: import from the .clean file, with the file name only

Your report imports your team’s .clean file (one header row, Export Survey Data) from the data folder of your project, using the path "data/…" and nothing else: no setwd(), no /Users/yourname/…. That is what makes the same code run on your teammates’ computers and your instructor’s.

ResourcesResources: other file types

The pattern holds for every file type: only the function changes. read_sav() from the haven package reads SPSS .sav files, read_csv() from readr (part of the tidyverse) is a faster read.csv(), and read_dta() reads Stata files. See the Posit data import cheatsheet.

9.3 🏈 The Lab

You watched the play above with example datasets. Now import the lab dataset yourself: a survey about what people believe about mental health. Everyone in the course uses the same file, so you can check your answers.

Ref’s kickoff. This lab is not graded, so I am here to help you check your own work. Try each step before you open my check. If your answer does not match, that is not a penalty. It is how you find out what to fix.

Before you start

  1. Get the lab data file, ANTH306_LayConceptionsMH_SYNTHETIC.xlsx, from your instructor. Put it in a folder called data inside your Lastname_FRI project folder.
  2. Open your RStudio Project and your lab .qmd file, and run your library() chunk. You need readxl.

9.3.1 Lab Play 1: Import the data

The file has more than one sheet. The survey answers are on the first sheet, Sheet1, which is the one read_excel() reads by default. Import it and name the object mh_raw. Then find out how many rows (people) and columns (variables) it has.

Go Ref’s check: how big is the dataset?

mh_raw should have 200 rows and 130 columns. Look in your environment tab: it shows the same two numbers next to mh_raw.

Resources👀 See the solution 
library(readxl)

mh_raw <- read_excel("data/ANTH306_LayConceptionsMH_SYNTHETIC.xlsx")

nrow(mh_raw)   # how many people?
ncol(mh_raw)   # how many variables?

9.3.2 Lab Play 2: View the variables

Look at the column names with names(), look at the first rows with head(), and get a summary of one variable, POLITICALBELIEFS, with summary(mh_raw$POLITICALBELIEFS).

Go Ref’s check: what should you see?
  • The first five column names are: ResponseId, StartDate, EndDate, Duration_sec, Progress. The last one is SERIOUS.
  • POLITICALBELIEFS has a minimum of -99 and a maximum of 6.
  • A minimum of -99 is not a real answer. The answers to this question run from 1 to 6, and -99 is the code for “Prefer not to say”. You will turn those codes into missing values (NA) in Lab Play 4.

9.3.3 Lab Play 3: Do the variable names match the survey?

This is the check that matters most. The column names in R come straight from the variable names that were typed into Qualtrics. If a name is misspelled, or a question was never named, you will see it here first (for example, a column called Q17 and no column called STIG3).

For the lab dataset, the survey’s variable names are listed on the sheet called codebook. Import that sheet, and compare its Variable column with names(mh_raw).

Go Ref’s check: do they match?
  • The survey variables in mh_raw should appear in the codebook, spelled the same way.
  • setdiff(names(mh_raw), mh_codebook$Variable) should return 9 names, and all of them should start with RELIGIOUS_IDENTITY. The codebook describes that group of columns in one line, so they do not match one by one. That is fine.
  • If you see any other name in that list, the data and the survey do not agree, and you would need to find out why.
Resources👀 See the solution 
names(mh_raw)                  # the VARIABLES in your dataset
head(mh_raw, 10)               # the first 10 people
summary(mh_raw$POLITICALBELIEFS)   # one variable: look at the minimum

mh_codebook <- read_excel("data/ANTH306_LayConceptionsMH_SYNTHETIC.xlsx",
                          sheet = "codebook")

# names that are in the data and NOT in the codebook
setdiff(names(mh_raw), mh_codebook$Variable)

9.3.4 Lab Play 4: Turn the missing codes into NA

Lab Play 2 found a minimum of -99 in POLITICALBELIEFS. In this survey, -99 means “Prefer not to say” and -50 means “Don’t know” (Name and Recode Variables in Qualtrics). If they stay as numbers, R will average them into every score. Replace both codes with NA, R’s word for missing, everywhere in the dataset, then run summary(mh_raw$POLITICALBELIEFS) again.

Go Ref’s check: did the codes go away?
  • summary(mh_raw$POLITICALBELIEFS) now shows a minimum of 1 and a new entry, NA's, with the number of people who did not answer.
  • The number of rows has not changed. Replacing a value with NA keeps the person; it only blanks that one answer.
Resources👀 See the solution 
mh_raw[mh_raw == -99] <- NA    # prefer not to say -> missing
mh_raw[mh_raw == -50] <- NA    # don't know -> missing

summary(mh_raw$POLITICALBELIEFS)

mh_raw == -99 finds every cell equal to -99, and <- NA writes NA into those cells. Transforming Your Data shows the tidyverse way to do the same thing, replace_with_na_all().

Caution Ref’s call: fouls to check if your numbers do not match
  • path does not exist → the file is not where the code says it is. Check that the file is inside a data folder in your project, that the name is spelled exactly the same, and that you opened your project (not only a file).
  • You have 1 column, or the wrong columns → you imported the wrong sheet. read_excel() reads the first sheet unless you add sheet =; check that your data are on the first sheet, or name the sheet you want.
  • could not find function "read_excel" → run library(readxl).
  • Your first row of data is question text → the file still has two header rows. See Export Survey Data and delete row 2 in the .clean file. (The lab dataset has one header row, so you should not see this in the lab.)

Ref’s final whistle. That is the end of the lab. Save your .qmd, render it, and back up your .qmd and .R files to the R Labs folder in your ELN before you quit RStudio.
